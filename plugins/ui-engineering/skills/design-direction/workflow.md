# Design direction workflow

Read the locked Design Brief and relevant Page Specs before producing `DESIGN-DIRECTION.md`. Determine product type, audience, primary task, brand personality, visual tone, information density, composition direction, image treatment, interaction tone, distinctiveness, provided references, and things to avoid.

When a user supplies a screenshot or product reference, create `REFERENCE-ANALYSIS.md` only if it changes the decision. Extract hierarchy, typography character, spacing rhythm, color strategy, component language, surface/border/shadow behavior, imagery, interaction, and density. Reinterpret the language for this product; do not clone assets or copy pixels/brand identity.

For existing UIs, read `ambition` from `orchestrate_ui` first ([ambition-levels.md](../../workflows/ambition-levels.md)). Under **Elevate** or **Reimagine** the direction must also contain a one-sentence thesis, a diagnosis of the current pages against the [default banlist](../../knowledge/visual-language/anti-slop/default-banlist.md), at least three [signature moves](signature-moves.md), the preserved invariants, and a per-page re-composition plan. A direction that only adjusts spacing, radii or shadows is a Refine direction and does not satisfy Elevate.

Direction states the desired experience. For landing/marketing/showcase work, redesigns, or any reference, continue to [Design Inspiration](../design-inspiration/workflow.md) to select archetype and design DNA; reference extraction follows [reference-extraction.md](../design-inspiration/reference-extraction.md) and [anti-copying.md](../design-inspiration/anti-copying.md).
